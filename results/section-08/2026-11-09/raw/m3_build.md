## What this shows

- **Only Plyer declares pyobjus** as a package dependency, as an extra for `ios` and `macosx`. Its install instructions and macOS CI use pyobjus's `master` branch from GitHub, not a PyPI release.
- **kivy-ios builds pyobjus `master`** and makes it a dependency of its `kivy` and `plyer` recipes. Kivy, KivyMD, Carvera Controller and kivy-tensorflow-helloworld get pyobjus that way on iOS, without naming it.
- **renpy-build compiles a pinned, patched pyobjus** into Ren'Py's Python for iOS and macOS. Ren'Py's docs offer it to game creators, so Ren'Py games can use it too. Those games aren't in Section 7's count (its Limits) or in this sample.
- **Carvera Controller's Xcode project links pyobjus directly** (`libpyobjus.xcframework`), besides building it through kivy-ios.

These are the places a move to Rubicon reaches outside the code. How each library is installed for iOS and macOS is B1.
